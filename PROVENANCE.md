# Provenance

This repository is the **white-label product**. Its history starts at a single
snapshot commit, on purpose.

## What the first commit is

- A snapshot of the product line's file tree as it stood on 27 November 2026,
  committed with **no prior history**.
- The product line grew out of a codebase first written for one contractor.
  Everything specific to that deployment was removed before the snapshot: its
  change log, its source documents and reports, its data-cleaning tools, its
  names, numbers and addresses. A grep for the deployment's identifying terms
  returned zero hits on the snapshot tree before it was committed.
- The earlier commits are **not** here because their files and messages carry
  that deployment's details. Deleting a file in a later commit does not remove
  it from history, so history was not carried over at all.
- Left out of the tree on purpose: `backups/` (database dumps), `.env`
  (secrets), editor and agent folders, and any customer spreadsheet or
  document. The three `.xlsx` files that remain (`demo_files/sample_boq.xlsx`,
  `fixtures/demo_boq.xlsx`, `fixtures/demo_annexure.xlsx`) are generated by
  `fixtures/build_fixtures.py` from a fictional company.

## What this means when reading the code

- Comments that cite `CLIENT_CHANGES.md` §0 blocks refer to the original
  deployment's change log. That file is **not** in this repository; the
  comment's own text says what was decided.
- Dates in comments and in ABOUT.md (August–November 2026) are when the work
  was done on the original line, before the snapshot.
- Nothing company-specific ships in code. The company's name, statutory
  identity, bank, logo, document prefix, sign-in domain and landing page are
  `/settings` values (see CLAUDE.md and ABOUT.md).

## Rule for everything that follows

No real client data enters this repository: not in files, fixtures, seed rows,
screenshots or commit messages. Demo data is fictional and is created through
the app's own routes.
