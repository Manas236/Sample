# Fixtures — the synthetic workbooks

Every workbook in this repository is **synthetic**: the names, quantities and
rates in it are fictional, generated by [`build_fixtures.py`](build_fixtures.py)
from [`demo_seed.py`](../demo_seed.py). They are committed, so a fresh clone
has them; rebuild them with:

```
python fixtures/build_fixtures.py
```

| File | What it is | Used by |
|---|---|---|
| `fixtures/demo_boq.xlsx` | The seeded BOQ — "Office Fit-out, Tower B", 3 sections, 24 lines, supply and installation priced separately, one line discounted by a negative escalation, an item number used twice in one section and a nil-priced line — laid out the way a contractor's workbook carries it. | `tests/test_fixtures.py`; `tests/test_boq_import.py` proves an import of it reproduces the seeded schedule line for line. |
| `fixtures/demo_annexure.xlsx` | The same schedule extended with nine RA claim columns, deliberately out of numeric order, and two `#VALUE!` cells an import report has to name. | `tests/test_fixtures.py`. |
| `demo_files/sample_boq.xlsx` | ~15 lines on two tabs (a summary cover and the schedule), with a parent line and its sub-items, blank cells and a **Discount %** column — for demonstrating *Import BOQ from Excel* live. | A person at `/boq/import`. |

## The discount column in the sample

The BOQ has no discount field of its own; a discount on a line is a **negative
escalation** on its base rate. The sample sheet carries the list rate
(*Supply Base Rate*), the *Discount %* and the net *Supply Rate* the amount is
worked from. The importer maps the two rate columns by their headings and
leaves *Discount %* as "— ignore —": the discount is already in the net rate, so
every amount checks and nothing needs a human.

## Without openpyxl

`openpyxl` is a runtime pin in `requirements.txt`. Without it the app still
boots and `/boq/import` says the reader is unavailable; the tests that need a
workbook skip with a message naming the missing package.
